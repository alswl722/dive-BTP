## 1. 목적

`data1(기업정보)` 시트에 있는 **종업원수·1인평균급여·국민연금 3종(가입/취업/퇴직)** 원본을,
심사 담당자가 실제로 판정에 쓸 수 있게 4개 관점(규모·처우·생산성·안정성)으로 시각화한다.

- **재무 4축·기술축·축8·축9 등 기존 스코어링 로직은 무영향**
- **종합점수 breakdown 에도 미편입** (설계 결정 근거는 §3 참조)
- 지원사업 KPI 핵심(고용창출·처우 개선)을 실측 지표로 심사관에게 노출

## 2. 왜 정식 축이 아니라 별도 탭인가

### 2.1 정식 축 신설 검토 (기각)

옵션 A: 재무 4축 → 5축 (`성장성 · 수익성 · 효율성 · 안정성 · 고용`)
- 🔴 **문제**: 성장기업의 정상 대규모 채용 → 회전율/이직률 감점 → 종합점수 왜곡
- 🔴 재무 4축 레이더/바 차트 · 가중치 UI 전면 재설계
- 🔴 발표에서 "왜 회전율이 안정성 감점인가" 재변론 필요

### 2.2 별도 축 (기술축·축8 병렬) 검토 (기각)

옵션 B: `종합점수 = 재무 4축 + 기술 2축 + 정합성 + 고용`
- 🔴 성장기업 왜곡 문제 여전
- 🟡 축 개수 늘어남 (composite radar 재설계)

### 2.3 별도 탭 (본 채택 ✅)

옵션 C: 스코어카드에 "고용" 탭 추가, 종합점수 breakdown 은 안 건드림
- 🟢 리스크 없음 (`SCORE_COLS` 불변)
- 🟢 정보 밀도 최대 (4개 섹션 · 6개 차트/카드)
- 🟢 배지·필터로도 재활용 가능

**최종 채택 결정 근거**: `docs/고용회전율_영업외손익_설계노트.md` 에 명시된
"성장기업 정상 채용을 안정성 감점으로 왜곡하지 않는다" 원칙을 유지하면서, 지원사업 KPI 로서
고용창출을 별도 노출할 필요가 있음.

### 3.2 4개 섹션 (`employment-tab.tsx`)

#### 섹션 1. 인력 규모·변화
- **StatCard 4개**: 종업원수 최근 · 5년 CAGR · 5년 증감 · 최근 이직률

- **핵심 질문**: "고용을 늘렸는가/줄였는가?" — 지원사업 KPI 심사 직결

#### 섹션 2. 처우·급여 수준
- **StatCard 3개**: 1인 평균급여 최근 · 5년 급여 CAGR · 업종·규모 대비 백분위
- **스파크라인**: 급여 5년 area chart
- **핵심 질문**: "서류상 우수 고용 주장을 급여 수준으로 감사 가능한가?"

#### 섹션 3. 인력 생산성
- **StatCard 2개**: 인당 매출 · 인당 영업이익
- **핵심 질문**: "자본 효율 관점에서 어느 수준인가?"
- **주의**: 매출 급증 기업도 대량 채용 시 인당 지표 정체 가능 (규모↑·수익↑ 축과 별개 참조 지표)

#### 섹션 4. 인력 안정성 · 국민연금 3종
- **회전율 요약 라인**: 고용 회전율(%) + 업종·규모 대비 순위
- **국민연금 5년 상세 표** (접힘형): 연도별 가입/취업/퇴직/이직률

## 4. 데이터 흐름

### 4.1 원본 (data1 기업정보 시트)
- `종업원수_YYYY` (2020~2024)
- `1인평균 연간급여_YYYY` (⚠️ 단위=원, 다른 재무는 천원)
- `국민연금 가입자수_YYYY / 취업자수_YYYY / 퇴직자수_YYYY`

### 4.2 파생 계산 (`backend/etl/features_finance.py`)

| 파생 컬럼 | 계산 | 용도 |
|---|---|---|
| `종업원수_최근` | 마지막 유효연도 값 | 규모 카드 |
| `종업원수_CAGR` | `safe_cagr(첫유효, 마지막유효)` | 규모 카드 |
| `종업원수_증감_5년` | 마지막 − 첫 유효연도 | 규모 카드 |
| `1인평균급여_최근` | 마지막 유효연도 값 (단위=원) | 처우 카드 |
| `1인평균급여_CAGR` | CAGR | 처우 카드 |
| `인당매출_최근` | 매출 ÷ 종업원수 (기업별 공통 최신 유효연도) | 생산성 카드 |
| `인당영업이익_최근` | 영업이익 ÷ 종업원수 | 생산성 카드 |

**중요한 방어**: `_last_common_valid_ratio()` 헬퍼로 기업별 공통 유효연도를 찾음 →
컬럼 기반 공통연도로만 잡으면 특정 기업의 종업원수_2024 결측 시 인당지표만 NaN 이 되는
버그 발생 (실제 발생해서 수정한 이슈).

### 4.3 백분위 (`backend/etl/scoring_finance.py` — `CONTEXT_PCT_COLS`)

3단 tier 적용 (SCORE_COLS 와 동일 정책):
1. **KSIC × 규모** 그룹이 MIN_GROUP 이상 → 최우선
2. **KSIC** 그룹만 사용 → 2순위
3. **전체 fallback** → 최후

파생 백분위:
- `고용회전율_백분위` (기존)
- `급여_백분위` (신규)
- `종업원수증가_백분위` (신규)
- `인당매출_백분위` (신규)

**왜 3단 tier**: 소상공인 vs 중견기업을 KSIC 만으로 묶으면 규모 자체가 백분위를 왜곡함
(소상공인은 자동으로 종업원 하위, 대기업은 자동 상위). 같은 KSIC 안에서 같은 규모끼리 비교해야
"우리 소상공인 중 급여 어느 수준" 같은 심사 의미 있는 질문이 가능.

### 4.4 API 응답 (`backend/app/schemas.py` — `Employment`)

```
class Employment(BaseModel):
    # 안정성 (배지 · 국민연금 펼침표) — 기존
    회전율백분위: float | None
    series: list[EmploymentYear] | None
    # 규모 · 변화 — 신규

    종업원수_증감_5년: float | None
    종업원수증가_백분위: float | None
    # 처우 — 신규
    급여_최근_원: float | None   # 단위=원 (원본 그대로)
    급여_CAGR: float | None
    급여_백분위: float | None
    # 인력 생산성 — 신규
```

## 6. 스코어링 정책 — 미포함 근거

**종합점수 breakdown 에 고용 필드는 없다**:
```
compositeScore.breakdown = {
    "성장성": ..., "수익성": ..., "효율성": ..., "안정성": ...,
    "R&D특허": ..., "NTIS": ..., "정합성": ...,
    # 고용 없음 (의도적)
}
```

**이유**:
1. 성장기업의 정상 대규모 채용을 이직률/회전율 감점으로 왜곡하면 심사 신뢰도 훼손
2. 고용 데이터는 "확인용 참고 지표"지 "판정 근거"가 아님 (심사관이 별도 눈으로 봄)
3. 시나리오별 임계값이 업종·규모에 크게 좌우돼 일률 적용 위험

**그 대신**:
- `passthrough` 로 원값 노출 (dictQuality.inconsistencies 와 같은 정보성 필드)
- 백분위(CONTEXT_PCT_COLS)는 계산해서 배지 포지션 바에만 사용
- 심사관이 종합점수와 "별개로" 확인
