# 기술력 축 설계노트 (R&D·특허 / 인증 / NTIS)

> 담당: 팀원 B · 발표 자료 및 팀 상호 참고용
> 관련 코드: `backend/etl/{aggregate_tech,features_tech,scoring_tech,milestones_tech}.py`, `dev_loader.py`

---

## 1. 개요

BTP 심사 브리핑의 **정보 비대칭**(서류상 역량 vs 실제 역량) 문제를 **기술력 관점**에서 해소한다. KODATA의 특허 원장·NTIS 이력·인증·연구조직 데이터를 기업별로 가공해 기술력 스코어카드와 **성공경로용 마일스톤**을 만든다.

재무 축(팀원 A)과 **같은 2단 구조**(파생 → 스코어링)를 따르고, 방어 계산은 A의 `finance_utils`를 그대로 재사용한다. **다른 점 하나**: 재무는 master_table이 이미 기업 1행 wide였지만, 기술력의 소스는 **기업당 다건인 원장**이라 "원장 → 기업 1행" 집계 단계(`aggregate_tech.py`)가 앞에 하나 더 붙는다.

파이프라인:
```
원장(patents/ntis/certs) → aggregate_tech(집계) → features_tech(파생) → scoring_tech(백분위·점수)
                                    └→ milestones_tech(시점 이벤트) → 성공경로 공급
```

핵심 원칙: **규칙 기반**, **절대 임계값 하드코딩 없음**(점수는 상대 등수), **원장이 진실**(집계컬럼 불신).

## 2. 데이터 특성 → 대응 결정 (왜 이렇게 방어했나)

재무 축과 마찬가지로 "데이터가 이래서, 우리는 이렇게 막았다"가 방어 서사.

| 데이터 특성 / 이슈 | 왜 문제인가 | 우리 대응 |
| --- | --- | --- |
| **특허 원장에 상표권·디자인권 혼입** (388건 중 특허권 281·상표권 71·디자인권 34·실용신안 2) | 상표·디자인은 R&D 산출물이 아님. 안 거르면 브랜딩 많은 기업이 기술기업으로 둔갑(예: 695는 전체 54건 중 27건이 비기술 IP) | 기술 IP(`특허권`·`실용신안권`)만 집계. `IP_TECH` 상수로 분리 |
| **master 특허"누적"컬럼이 비단조** (117: 0→2→**1**→2→0, 감소함) | 누적이라면 단조증가해야 하는데 감소 → 누적이 아니라 flow이거나 오염 | **master 특허컬럼 폐기, 원장(patents)만 사용.** 출원/등록 건수·시점 모두 원장 기준 |
| **NTIS 주관 스냅샷 중복** (원본 170행 → 실제 59과제, 2.9배) | 기준일자별로 같은 과제가 여러 행. 그냥 세면 수주건수 3배 부풀려짐 | `(company_id, 총연구기간, 사업명)`으로 dedup 후 집계 |
| **NTIS 위탁에 사업명·기간 컬럼 없음** | 주관과 같은 키로 dedup 불가 | 서술 컬럼으로 dedup, 주 산출물은 건수가 아니라 **산학협력 여부**(boolean, 중복에 강건) |
| **특허 등록 vs 공개 혼재** (등록 260 / 공개 128) | '공개'는 출원 계류 상태(등록 아님) | 등록 = `reg_status='등록'`만(=`registered_date` 존재와 정확히 일치 확인). 출원≠등록 구분해 **전환율** 계산 |
| **첫 특허가 설립일보다 앞섬** (695: 설립 17년 전 출원) | 대표자 개인 명의 IP 이력이 법인 설립 전부터 존재 → 첫특허_업력이 음수 | 음수를 **0으로 clip**("설립 즉시 IP 보유"로 간주). 원값 왜곡 방지 |
| **인증이 유/무만, 취득일 없음** | 마일스톤 순서에 못 넣음 | 인증은 **현재 상태(배지)로만**. 마일스톤 체인에서 제외 |
| **인증 전원 보유** (샘플 11개 전원 ≥1개 보유) | 인증 보유수 자체는 변별력 0 | 인증을 **점수화하지 않음**. 대신 인증-실체 괴리 플래그로 전환 |
| **NET/NEP 전원 무** | 샘플 정보량 0 | 코드는 유지(본선 대비), 샘플 점수엔 미반영 |

## 3. 공통 방어 모듈 재사용 (`finance_utils`)

팀원 A가 만든 방어 함수를 그대로 import한다(재구현 안 함).
- `safe_ratio` : R&D집약도(R&D비/매출)·등록전환율(등록/출원) — 분모 0/음수 → NaN
- `slope` : R&D집약도 추세 — 결측 위치 유지, 유효 2점 미만 NaN

→ 재무·기술 두 축이 같은 방어 로직을 공유하므로 결측·0·음수 처리 일관성 보장.

## 4. 파생컬럼 — 무엇을 재고, 왜 만들었나

### 축4 R&D·특허
- **R&D집약도**(연구개발비÷매출) + **추세**: "돈을 얼마나 R&D에 쓰는가"와 그 방향. 규모 무관 비교 가능.
- **특허 출원/등록 건수**(기술 IP): 원장 기준 실제 건수(master 누적컬럼 불신).
- **등록전환율**(등록÷출원): 출원만 많고 등록 못 하는 기업 구분. IP의 **질**.
- **첫특허_업력**: 설립 후 몇 년째 첫 출원. 조기 R&D 착수 여부(낮을수록 좋음).

### 축5 인증 — 점수가 아니라 신호
- **인증-실체 괴리 플래그** ★: 핵심인증(이노비즈/메인비즈/벤처) 보유인데 **등록특허 0 AND 국가R&D 0**. *"인증은 있는데 실체가 없는"* 기업 = **발제사 '정보 비대칭'의 정확한 타깃**.
  - 판정선은 **절대 0 기준**(백분위 아님): 소표본에서 백분위 하위는 불안정하고, "0건"은 해석이 명확해 담당자가 신뢰.
  - 샘플은 큐레이션된 우수기업이라 플래그 0곳 → 본선에서 작동. **경계 사례**(등록특허 소수)는 플래그 대신 **연속 점수**가 포착(1878이 R&D특허 최하위로 잡힘).

### 축6 NTIS
- **주관 과제수·정부연구비·부처다양성**: 정부 R&D 수주력. 부처다양성 = 수주 폭.
- **위탁 과제수·산학협력 여부**: 협업 네트워크.
- ⚠️ 정부연구비 단위는 **원**(재무 지표는 천원) — 혼용 주의.

## 5. 스코어링 설계 근거 (`scoring_tech.py`)

재무 축과 동일하게 **업종내 백분위 + fallback**(그룹 < 5면 전체 대비). 방향 자동 보정(낮을수록 좋은 첫특허_업력은 `100-백분위`).

**축 = R&D·특허 / NTIS 두 개.** 인증은 점수화하지 않고 배지/플래그로 passthrough(전원 보유라 변별력 0). `scoring_finance`의 `자본잠식_플래그`와 동일하게 `인증실체괴리_플래그`도 점수 미반영 리스크 배지.

**종합점수는 만들지 않되(재무 축과 동일 철학) 두 기술 축은 그대로 breakdown에 유지** — 두 기술 축이 갈리는 게 핵심. 실증: 117은 특허 72.0(최상)인데 NTIS 29.5(하위) = "특허 강함/국가R&D 약함", 616은 그 반대. 이 어긋남이 사라지면 안 되므로 두 축은 종합점수의 원자료로만 쓰이고, 그 자체는 항상 나란히 노출된다.

⚠️ **갱신**: 심사 스크리닝용 보조 지표로 종합점수를 도입했다(`backend/app/services/composite_score.py`). 재무 4축·기술 2축·축8을 최저축 캡 방식(`min(가중평균, 최저축+15)`)으로 합산 — 117·616 같은 축 어긋남 사례가 캡에 걸려 종합점수도 낮게 나오도록 설계했다. 상세: [종합점수_설계노트.md](종합점수_설계노트.md).

⚠️ 샘플은 업종당 1~4개사라 **전원 fallback(전체)** 경로. 본선 대규모에서 업종내 백분위 작동. 발표에서 명시.

## 6. 마일스톤 — 성공경로 공급 (`milestones_tech.py`)

기술력 데이터의 시점 컬럼(연구조직 등록일·특허 출원/등록일·NTIS 수주)에서 **시점이 찍힌 이벤트**를 뽑는다. 설계의 '성공 = 전이' 정의에서 전이 직전에 밟는 **디딤돌**이 이것.

출력: `(company_id, event_type, event_date, detail)` long. 미달성 마일스톤은 행 없음.

실증(2379의 14년 R&D 사다리): 첫특허출원(2006) → 첫특허등록(2008) → 전담부서설치(2015) → 국가R&D첫수주(2020) → 부설연구소설립(2020). **전담부서→부설연구소 승격 경로**가 데이터에 실재.

## 8. ★ 특허 데이터에서 더 뽑을 수 있는 신호 (미구현, 검증 완료)

현재 특허를 **R&D 역량 점수**로만 쓰고 있으나, 같은 원장에서 **다른 축의 판단 재료**가 더 나온다. 아래는 샘플로 실제 계산해 확인한 것(값은 본선에서 재산정).

| 신호 | 계산 | 무엇을 판단하나 | 왜 중요 |
| --- | --- | --- | --- |
| **IP 구성비** | 종류별 비중(특허/실용신안/상표/디자인) | **기업 성격** — 기술형 vs 브랜드형 vs 디자인형 | 우리가 '노이즈'로 걸러낸 상표·디자인의 **비중 자체가 정보**. 예: 한 기업은 IP 5건 중 3건이 디자인권(60%)이라 기술 R&D 기업이 아님에도 인증·부설연구소 보유 → **축8 정합성 판정의 강력한 근거** |
| ★ **특허 소멸률** | `등록 & is_valid=False` ÷ 등록 | **재무 스트레스·리스크** | 등록 특허를 유지하려면 **연차료**가 든다. 이를 포기(소멸)한다는 건 자금 압박 또는 해당 기술 철수 신호. 샘플에서도 기업별 0~12.5%로 뚜렷이 갈림. 재무 악화 시점과 겹쳐보면 **조기경보** |
| ★ **최근 활동성** | 최근 3년 출원 건수 / 마지막 출원연도 | **R&D 지속성** ("과거의 영광" 판별) | 누적 건수는 과거 실적. 누적 22건인데 마지막 출원이 2022년인 기업 vs 누적 58건 중 21건이 최근인 기업은 전혀 다름. **누적 숫자로는 절대 안 보이는 정체 신호** |
| **출원→등록 리드타임** | 등록일 − 출원일 | 사업화 속도·우선심사 활용 | 샘플 평균 1.53년. 짧으면 빠른 권리화(사업화 의지) |
| **권리 귀속** | `relation_code`(본인/대표이사/임원) | IP 자산의 실체 | 대표이사·임원 **개인 명의** 특허가 존재. 법인 자산이 아니므로 "이 회사의 IP"로 세면 과대평가 |

> **미사용 컬럼 2개를 여기서 살린다**: `is_valid`(등록유효여부), `relation_code`(회사와의관계코드). 기존 집계는 둘 다 안 쓰고 있었다.
> **핵심**: 특허는 R&D 축 전용이 아니라 **R&D 역량 / 기업 성격(축8) / 재무 리스크 / 지속성** 네 축에 걸친다.

## 8-1. ★ 기술 도메인 축 — "얼마나"가 아니라 "어느 분야에서"

기존 축4·5·6은 전부 **강도(얼마나 많이/잘)** 만 측정하고 **분야(어느 기술영역)** 를 안 본다. 심사자가 *"이 기업이 우리 사업 분야에 맞나"* 를 판단하려면 도메인 식별이 필요하다.

### 발견: 국가 공식 기술분류가 데이터에 이미 있다 (미사용이었음)

NTIS 주관 시트의 **`과학기술표준분류명`**(`tech_classification`) = **국가과학기술표준분류체계**(정부 공식 taxonomy).
**결측 3/170(1.8%), 고유값 31개** — 품질 우수.

기업별로 뽑으면 기술 정체성이 즉시 드러난다(dedup 과제 기준):

| 기업 | 표준분류 | 도메인 |
| --- | --- | --- |
| 695 | 바이오센서·생체재료·바이오생체재료 | 바이오 |
| 1049 | 소프트웨어·조선해양 S/W·가상현실·수중추진 | 디지털 |
| 616 | 에너지소재기술·수소·인발기술 | 탄소중립 |
| 672 | 대기오염방지·가스에너지·해양구조물 | 환경·에너지 |
| 2379 | 재난안전장비·해양환경/안전·위험감지 | 해양안전 |
| 1178 | 배관용 요소부품·유공압 부품 | 기계부품 |

**`주관부처명`도 도메인 신호**: 해양수산부 76 / 중기부 59 / 과기부 15 / 산업부 9 (부산 특성상 해양 우세).

### BTP 4대 중점사업 매핑이 성립한다

```
탄소중립 산업체질 강화 ← 616(수소·에너지소재), 672(대기오염방지·가스에너지)
  └ 바이오 라이프     ← 695(바이오센서·생체재료), 1786(치료/진단기기)
디지털전환 체계적 지원 ← 1049(SW·VR·조선해양SW)
지역특화산업 혁신선도  ← 2379·2080·1730(해양·선박), 1178(기계부품)
```
→ 발제사 전략과 직접 연결 = 문제정의(20점) 직결.

### ⚠️ 3단 폴백 필수
1730·1878은 **NTIS 과제 0건 → 표준분류 없음.**
`NTIS 표준분류` → 없으면 `KSIC 업종` → 없으면 `주요제품·사업목적 텍스트` → **그래도 없으면 "기술분야 미상" 명시**(임의 추정 금지).

### 한계
- **특허의 기술분야는 못 본다** — 특허 원장에 **IPC/CPC도, 특허번호도 없음** → 외부 특허DB 매칭 불가. 기술분야는 **NTIS 기반**임을 화면에 명시.
- `주요제품`이 1786·1878 결측 → 텍스트 폴백도 한계.
- 표본 편중(해양수산부 76/170)은 부산 특성. 일반화 금지.
