## 0. 왜 이 통합이 시급한가 — 지금 화면이 틀린 숫자를 보여주고 있다

기술축 모듈은 머지됐으나 **어디서도 import되지 않는다.** 그래서 현재 `frontend/components/scorecard/tabs/rnd-tab.tsx`가 표시하는 값은 원본 오류를 그대로 노출한다.

| 화면 표시 | 현재 출처 (`company_view.py`) | 문제 | 교체 대상 |
|---|---|---|---|
| 특허 등록/출원 | master `특허등록건수(누적)` | **비단조(누적 아님)** + **상표·디자인 포함** | `특허등록_건수` / `특허출원_건수` |
| NTIS 주관/위탁 | `NTIS주관_행수` | 스냅샷 중복 → **약 2.9배 부풀림**(170행 = 실제 59과제) | `NTIS주관_과제수` / `NTIS위탁_과제수` |

→ **이 통합은 기능 추가가 아니라 오류 수정이다.**

## 1. 호출 방법

```python
import aggregate_tech, features_tech as ft, scoring_tech as st, domain_tech, milestones_tech

agg    = aggregate_tech.build(tables)                                   # 원장 → 기업1행
feat   = ft.compute_features(agg, tables["company_yearly_metrics"],
                             tables["companies"])                       # 파생지표
scores = st.compute_scores(feat, st._align_ksic(feat, tables["companies"]))  # 백분위·축점수
domain = domain_tech.build(tables)                                      # 기술 도메인
events = milestones_tech.build(tables)                                  # 마일스톤(성공경로용)
```

- `tables` = `dev_loader.load_tables()` 또는 DB `read_sql_table` 결과 dict (**동일 스키마**).
- 조인 키는 **`company_id`**(영문). `company_view.py`의 `master_table` 키는 `기업일련번호`이므로 **머지 시 키 정렬 필요**(값은 동일).

## 2. 산출 필드 (company 단위)

### 2.1 R&D·특허 (축4)

| 필드 | 타입 | 의미 | 비고 |
|---|---|---|---|
| `특허출원_건수` | int | 기술 IP 출원 | **상표·디자인 제외**(특허권+실용신안만) |
| `특허등록_건수` | int | 등록 완료 | `reg_status='등록'`만(공개=계류 제외) |
| `특허등록전환율` | float | 등록÷출원 | 출원 0 → null. **특허의 질** |
| `특허_최근출원건수` | int | 최근 3년 출원 | ★활동성 |
| `특허_최근출원비중` | float | 최근÷전체 | ★낮으면 과거 실적 의존 |
| `특허_활동공백년수` | float | 마지막 출원 이후 경과 | ★클수록 R&D 정체 |
| `특허소멸률` | float | 소멸÷등록 | ★연차료 미납 = **자금압박·기술철수 신호** |
| `첫특허_업력` | float | 설립 후 첫 출원까지(년) | 설립 전 출원은 0 clip |
| `R&D집약도` | float | 연구개발비÷매출(최근) | 매출 0/음수 → null |
| `R&D집약도추세` | float | 5개년 기울기 | |

### 2.2 인증 (축5)

| 필드 | 타입 | 비고 |
|---|---|---|
| `인증_보유수` | int | 6종 중 보유 개수 |
| `인증_핵심보유` | bool | 이노비즈·메인비즈·벤처 중 1개 이상 |
| `인증실체괴리_플래그` | bool | ★**핵심인증 보유 + 등록특허 0 + 국가R&D 0** = 서류상 R&D기업, 실적 없음 |

> 인증은 **점수화하지 않는다**(샘플 전원 보유 → 변별력 0). 배지/플래그로만 노출.

### 2.3 NTIS (축6)

| 필드 | 타입 | 비고 |
|---|---|---|
| `NTIS주관_과제수` | int | **dedup 후**(원본 행 수 아님) |
| `NTIS주관_정부연구비` | float | **단위 = 원**(재무는 천원 — 혼용 주의) |
| `NTIS주관_부처다양성` | int | distinct 부처 수 |
| `NTIS위탁_과제수` | int | |
| `산학협력_여부` | bool | 위탁 대학 공동연구 |

### 2.4 기술 도메인 (축4-1, 신규)

| 필드 | 타입 | 비고 |
|---|---|---|
| `주력기술분야` | str | NTIS 과학기술표준분류 롤업 |
| `도메인_출처` | str | `표준분류` / `KSIC추정` / `미상` — ★**화면에서 반드시 구분 표기** |
| `기술분야_수` | int | 다각화 정도 |
| `기술집중도` | float | HHI(0~1). 1=단일분야 전문 |
| `기술분야_목록` | str | `; ` 구분 |
| `BTP중점사업` | str | 부산TP 4대 중점사업 정렬(복수 가능) |
| `주력부처` / `부처다양성` | str/int | 정책 도메인 |

### 2.5 점수 (scoring_tech)

| 필드 | 범위 | 비고 |
|---|---|---|
| `R&D특허점수` | 0~100 | 업종내 백분위 + fallback |
| `NTIS점수` | 0~100 | 동일 |
| `pct_*` | 0~100 | 지표별 백분위(드릴다운용) |
| `백분위기준` | str | `업종내` / `전체fallback` — ★**표본 부족 표시용** |

### 2.6 마일스톤 (성공경로용)

`(company_id, event_type, event_date, detail)` long 형식.
`event_type` ∈ {전담부서설치, 부설연구소설립, 첫특허출원, 첫특허등록, 국가R&D첫수주}

## 3. 프론트 표시 권장 (rnd-tab)

1. **핵심 카드**: 등록 특허 앞·출원 뒤 + **"상표·디자인 제외" 명시**(원본과 수치가 달라 보이는 이유)
2. **출원→등록 퍼널**: 전환율 시각화
3. 🚩 **경고 배지**
   - `인증실체괴리_플래그` → *"인증 보유 / 등록특허 0 / 국가R&D 0"*
   - `특허_활동공백년수` 큰 경우 → *"최근 N년간 출원 없음"*
   - `특허소멸률` 높은 경우 → *"등록특허 N건 권리 소멸"*
4. **기술분야 뱃지**: `주력기술분야` + `BTP중점사업`. `도메인_출처=KSIC추정`이면 **"업종 기반 추정" 표기**
5. **표본수 병기**: `백분위기준=전체fallback`이면 *"동종 표본 부족"* 표시

```bash
python backend/etl/aggregate_tech.py
```
