## 0. 한눈에 — 무엇을 만드나

A(재무 3축)와 **완전히 같은 2단 구조**를 기술력 버전으로 복제한다.

```
[원장 3종]  patents / ntis_lead / ntis_consigned / company_certifications
    │  (B만의 추가 단계) 원장 → 기업 1행 집계
    ▼
aggregate_tech.py     원장 다건 → 기업×지표 wide
    ▼
features_tech.py      compute_features(df) → 파생 지표      ← finance_utils 재사용
    ▼
scoring_tech.py       compute_scores(feat, ksic) → 백분위 + 축점수 + 플래그
    ▼
company_view.py 통합   build_companies에 기술축 병합 → API
    +
milestones_tech.py    마일스톤 이벤트(시점) 추출 → 성공경로 담당에게 공급
```

**A와 다른 점 딱 하나**: A의 입력은 master_table(기업 1행 와이드)이었지만, B의 입력은 **원장(기업당 다건)** 이라 "집계" 단계(`aggregate_tech.py`)가 앞에 하나 더 붙는다.

## 3. ★ 인증-실체 괴리 플래그 (축5 핵심, 설계.md §10.2)

**규칙기반 이진 판정 (백분위 아님).** 개념정의 대장 #12 확정 필요.

```
괴리 = 핵심인증(이노비즈/메인비즈/벤처) 보유  AND  실체지표 하위
      실체지표 = { R&D집약도, 특허등록누적, 연구원수, NTIS주관과제수 }
      "하위" 판정선: (결정 필요) 하위 25%? 절대 0? 복합?
```

→ *"이노비즈인데 R&D비 하위·특허 0·NTIS 0"* = 서류 vs 실제 역량 괴리. **발제사 '정보 비대칭' 정면.**
→ ⚠️ 소표본에선 백분위 하위가 불안정 → **절대 0 기준(특허 0건 AND NTIS 0건 AND R&D집약도 하위)** 을 1차안으로, 본선에서 백분위 병행.

## 4. 스코어링 (scoring_tech) — A와 같되 다르게 갈 것

A의 `scoring_finance.py` 패턴(업종내 백분위 + fallback) 복제. **단, 3가지 조정:**

1. **점수 축은 3개**: R&D·특허 점수 / (인증은 점수 대신 플래그) / NTIS 점수. 인증은 백분위 부적합(전원 보유).
2. **플래그는 passthrough** — `자본잠식_플래그`가 그랬듯 `인증실체괴리_플래그`도 점수 미반영, 배지용.
3. **방향(up/down)**: 전부 up(높을수록 좋음). `등록전환율`·`부처다양성` 등.

> ⚠️ 샘플은 업종당 1~4개사라 **전원 fallback(전체)** — A와 동일 한계. 본선에서 업종내 작동. 발표 시 명시.

## 10. 백로그 — 특허 추가 신호 4종 (P7, 검증 완료·미구현)

같은 특허 원장에서 **R&D 외 다른 축**의 판단 재료가 더 나온다. 상세 근거는 설계노트 §8.

| 우선 | 신호 | 계산 | 판단 축 |
|---|---|---|---|
| **1** | **최근 활동성** | 최근 3년 출원 건수 / 마지막 출원연도 | R&D **지속성** — "과거의 영광" 판별. 누적 22건인데 마지막 출원 2022년인 기업 존재 |
| **2** | **특허 소멸률** | `등록 & is_valid=False` ÷ 등록 | **재무 스트레스** — 연차료 포기 = 자금압박/기술철수. 샘플 0~12.5%로 갈림 |
| 3 | **IP 구성비** | 특허/실용신안/상표/디자인 비중 | **기업 성격**(축8 정합성) — IP의 60%가 디자인권인데 인증·연구소 보유한 사례 존재 |
| 4 | 리드타임 · 권리귀속 | 등록일−출원일 / `relation_code` | 사업화 속도 / IP 자산 실체(대표이사·임원 개인 명의 18건) |

> **미사용 컬럼 `is_valid`·`relation_code`를 여기서 살린다.**
> 추천: **1·2번 먼저** — 계산이 단순하고, "누적 숫자만 보면 놓치는 것"이라 발표 스토리로도 강함.
