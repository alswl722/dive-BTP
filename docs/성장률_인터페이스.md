# 성장률 인터페이스 계약 (축1 민지 → 축9 형우)

> 목적: 축9 flag 판정이 축1(성장성) 산출물을 **소비만** 하고 재계산하지 않기 위한 인터페이스 스펙.
> 상태: **초안 (TODO — 민지 합의 필요)** · 관련 코드: `backend/app/services/axis9.py:GrowthSignal, growth_signals_from_axis1()`

## 1. 배경

CLAUDE.md 원칙5·축9 설계노트에 따라:
- 축1 재무축 방어(음수 CAGR 금지, 자본잠식 등)는 민지 `finance_utils.py` 소유
- 축9는 성장률을 직접 계산하면 방어 로직 중복·오류 위험
- **축9는 축1 산출값만 받아 truth table 판정** (설계노트 §4)

이 문서가 두 축의 계약 지점. 민지 산출 컬럼명·타입·null 정책을 확정한다.

## 2. 인터페이스 스펙 (초안)

### 2.1 형식

`pandas.DataFrame` — Phase 5 통합 시점에 `features_finance` 또는 별도 뷰로 노출.

### 2.2 컬럼

| 컬럼명 | 타입 | 범위 | Null 허용 | 의미 |
| --- | --- | --- | --- | --- |
| `company_id` | int | — | ❌ | 기업일련번호 (조인 키) |
| `growth_score` | float | 0.0 ~ 100.0 | ✅ | 축1 종합 성장성 점수 (백분위 기반). **축9 flag 판정에 사용** |
| `revenue_cagr` | float | -1.0 ~ ∞ | ✅ | 매출액 5년 CAGR (decimal, e.g. 0.15 = 15%). 참고·발표용 |
| `revenue_delta` | float | -∞ ~ ∞ | ✅ | 최근 5년 매출 증가액 (천원 단위). 참고·발표용 |

### 2.3 Null 정책

- **재무 데이터 결측·자본잠식 등 축1 방어에 걸린 케이스** → 해당 컬럼 `NaN`
- 축9는 `growth_score is None` 시 flag = `"unknown"` 처리 (판정 유예)
- 이 경우 담당자 화면에 "성장률 미제공 (재무 데이터 확인 필요)" 표시

### 2.4 예시

```python
company_id  growth_score  revenue_cagr  revenue_delta
     117          25.3        -0.02       -1500000.0
    1178          80.5         0.18       12000000.0
    1786          45.0         0.06        2500000.0
    2379           NaN          NaN             NaN   # 자본잠식 방어
```

## 3. 축9가 소비하는 방식

`axis9.growth_signals_from_axis1(df)` 헬퍼가 위 DataFrame을 `dict[int, GrowthSignal]`로 변환:

```python
@dataclass(frozen=True)
class GrowthSignal:
    company_id: int
    growth_score: float | None
    revenue_cagr: float | None
    revenue_delta: float | None
```

`axis9.classify_flags_batch(metrics_df, growth_signals=<위 dict>, config)` → flag DataFrame 반환.

**계약 위반 시 동작**:
- 컬럼 누락 → `ValueError("축1 인터페이스 컬럼 누락: {...}")` 즉시 raise
- Null 값 → `GrowthSignal.growth_score = None` → flag = `"unknown"`

---

## 4. 왜 growth_score를 우선 쓰나

flag 판정에는 **`growth_score` 하나만 사용** (`revenue_cagr`·`revenue_delta`는 참고).

이유:
- **스코어카드 통합 관점**: 축1이 이미 백분위 기반으로 정규화한 값 → 축9는 그 위에 이분법(정체/성장) 임계값만 적용
- **재무 방어 재사용**: 음수 CAGR·자본잠식·0나눗셈 등 축1 방어 로직이 이미 반영된 값
- **본선 재산정 용이**: 임계값 하나(`growth_score_stagnant`)만 조정하면 됨 (`axis9_thresholds.yaml`)

---

## 5. Flag 판정 로직 (계약 소비 지점)

```python
if signal.growth_score is None:
    growth_state = "unknown"
elif signal.growth_score < config["flag_logic"]["growth_score_stagnant"]:  # default 30.0
    growth_state = "stagnant"
else:
    growth_state = "growing"

# 이후 (is_repeat × growth_state) truth table로 flag / cleared / observe / normal 판정
```

**임계값 30.0의 의미**: growth_score 하위 30% = 정체. 본선 재산정 대상 (config 파라미터).
