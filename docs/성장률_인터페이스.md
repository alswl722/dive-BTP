# 성장률 인터페이스 계약 (축1 민지 → 축9 형우)

> 목적: 축9 flag 판정이 축1(성장성) 산출물을 **소비만** 하고 재계산하지 않기 위한 인터페이스 스펙.
> 관련 코드: `backend/app/services/axis9.py:GrowthSignal, growth_signals_from_axis1()` · 민지 소스: `backend/etl/{finance_utils,features_finance,scoring_finance}.py`

---

## 1. 배경

CLAUDE.md 원칙5·축9 설계노트에 따라:
- 축1 재무축 방어(음수 CAGR 금지, 자본잠식 등)는 민지 `finance_utils.py` 소유 (구현 완료·검증 완료 — `ETL_인터페이스.md`에서 `--source db` 스팟체크 5건 통과 표시)
- 축9는 성장률을 직접 계산하면 방어 로직 중복·오류 위험
- **축9는 축1 산출값만 받아 truth table 판정** (설계노트 §4)

이 문서가 두 축의 계약 지점. 민지 실제 산출 shape(한글 컬럼)에 맞춰 정리.

## 2. 인터페이스 스펙

### 2.1 형식

`pandas.DataFrame` — 민지 `scoring_finance.compute_scores()` 산출 + `features_finance.compute_features()` 파생컬럼 조인.

### 2.2 컬럼 (팀 컨벤션: 한글)

| 컬럼명 | 타입 | 범위 | Null | 필수 | 출처 · 의미 |
| --- | --- | --- | --- | --- | --- |
| `기업일련번호` | int | — | ❌ | ✅ | 조인 키 (모든 팀 산출물 공통) |
| `성장성점수` | float | 0.0 ~ 100.0 | ✅ | ✅ | `scoring_finance.py` 종합 성장 점수 (백분위 평균). **축9 flag 판정에 사용** |
| `매출_CAGR` | float | -1.0 ~ ∞ | ✅ | ⭕ | `features_finance.py` decimal (e.g. 0.15 = 15%). 참고·발표용. join 안 돼 있으면 스킵 |
| `매출_증가액` | float | -∞ ~ ∞ | ✅ | ⭕ | 5년 매출 증가액 (천원). 참고용. 없으면 스킵 |

**필수 컬럼 2개** (`기업일련번호`, `성장성점수`)만 있으면 축9 flag 판정 가능. 나머지는 화면 참고·발표 자료용.

### 2.3 Null 정책

민지 `finance_utils.safe_cagr`·`safe_ratio`가 다음 케이스에서 `NaN` 반환 → 그대로 소비:
- 재무 데이터 결측
- 자본잠식 (자본총계 ≤ 0)
- 시작값 0/음수 (CAGR 발산 방지)
- inf 값

축9는 `pd.isna(성장성점수) → None → status="unknown"` 로 처리 → 담당자 화면에 "성장률 미제공 (재무 데이터 확인 필요)" 표시.

### 2.4 예시

```
기업일련번호  성장성점수  매출_CAGR   매출_증가액
     117          25.3        -0.02   -1500000.0     ← 정체 (flag 후보)
    1178          82.5         0.18   12000000.0     ← 성장 (cleared)
    1786          15.0        -0.02    -500000.0     ← 정체 (반복+정체=flag)
    2379           NaN          NaN          NaN     ← 자본잠식 (unknown)
```

## 3. 축9가 소비하는 방식

`backend/app/services/axis9.py:growth_signals_from_axis1(df)` 헬퍼가 위 DataFrame을 `dict[int, GrowthSignal]`로 변환:

```python
@dataclass(frozen=True)
class GrowthSignal:
    company_id: int
    growth_score: float | None      # 성장성점수 매핑
    revenue_cagr: float | None      # 매출_CAGR 매핑 (옵션)
    revenue_delta: float | None     # 매출_증가액 매핑 (옵션)
```

**설계 결정**: DataFrame 컬럼은 팀 컨벤션 따라 **한글**, 내부 dataclass 필드는 Python 관례 따라 **영문**. 매핑은 `growth_signals_from_axis1()`가 담당.

```python
# axis9.classify_flags_batch(metrics_df, growth_signals=<위 dict>, config)
# → flag DataFrame 반환
```

**계약 위반 시 동작**:
- 필수 컬럼(`기업일련번호`, `성장성점수`) 누락 → `ValueError("축1 산출 필수 컬럼 '{col}' 없음")` 즉시 raise
- Null 값 → `GrowthSignal.growth_score = None` → flag = `"unknown"` (안전 fallback)

---

## 4. 왜 성장성점수만 flag 판정에 쓰나

flag 판정에는 **`성장성점수` 하나만 사용** (`매출_CAGR`·`매출_증가액`은 참고).

이유:
- **스코어카드 통합 관점**: 축1이 이미 백분위 기반으로 정규화한 값 → 축9는 그 위에 이분법(정체/성장) 임계값만 적용
- **재무 방어 재사용**: 음수 CAGR·자본잠식·0나눗셈 등 축1 방어 로직이 이미 반영된 값
- **본선 재산정 용이**: 임계값 하나(`growth_score_stagnant`)만 조정하면 됨 (`axis9_thresholds.yaml`)

## 5. Flag 판정 로직 (계약 소비 지점)

```python
if signal.growth_score is None:
    growth_state = "unknown"
elif signal.growth_score < config["flag_logic"]["growth_score_stagnant"]:  # default 30.0
    growth_state = "stagnant"
else:
    growth_state = "growing"

# 이후 (is_repeat × growth_state) truth table로 flag / cleared / observe / normal 판정
```

**임계값 30.0의 의미**: 성장성점수 하위 30% = 정체. 본선 재산정 대상 (config 파라미터).
