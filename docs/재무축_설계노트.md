# 재무 축 설계노트 (성장성·수익성·효율성·안정성)

> 담당: 팀원 A (재무 3축 + 공통 방어 모듈) · 발표 자료 및 팀 상호 참고용
> 관련 코드: `backend/etl/finance_utils.py`, `features_finance.py`, `scoring_finance.py`

---

## 1. 개요

BTP 심사 브리핑의 문제 중 **정보 비대칭**(담당자가 서류·지표만으로 우수기업을 가려내야 함)을 재무 관점에서 해소한다. KODATA 재무제표(2020~2024)를 기업별로 가공해 **재무 4축 스코어카드**를 만든다.

- **파생컬럼 24개** (`features_finance.py`) — 재무제표 원값을 심사에 쓸 신호로 변환
- **정규화·축 점수** (`scoring_finance.py`) — 업종 대비 백분위 → 성장성·수익성·효율성·안정성 4축 점수
- **공통 방어 모듈** (`finance_utils.py`) — 팀원 B(기술력 축)도 재사용

핵심 원칙: **규칙 기반**, **절대 임계값 하드코딩 없음**(점수는 상대 등수), **컬럼·연도 하드코딩 없음**(부분일치 매핑 + config).

## 2. 데이터 특성 → 대응 결정 (왜 이렇게 방어했나)

EDA에서 확인된 데이터 특성마다 대응을 설계에 반영했다. **"데이터가 이래서, 우리는 이렇게 막았다"**가 이 프로젝트의 핵심 방어 서사.

| 데이터 특성 / 이슈 | 왜 문제인가 | 우리 대응 |
| --- | --- | --- |
| **이익 음수** (영업이익 18/55·당기순이익 10/55) | 음수 밑 거듭제곱근이 깨져 CAGR 계산 불가 | **이익류 CAGR 금지.** 이익은 비율(이익률·ROA·ROE)·연수(흑자지속성)·기울기(추세)로만 |
| **자본총계 0/음수** (자본잠식) | 부채비율(부채/자본) 분모가 0/음수면 값 폭발·부호 반전 | `safe_ratio`가 분모≤0 → **NaN 자동 처리** + `자본잠식_플래그` 별도 |
| **매출 시작값 0 가능** | CAGR·성장률 분모 0 → 발산 | `safe_cagr`/`safe_ratio`가 시작값≤0 → NaN |
| **비율 컬럼 이상치** | 한 해 마진이 튀면 추세 기울기 왜곡 | 수익성추세: **연도별 횡단면 윈저라이징**(각 연도를 기업들 사이 극단값 clip) 후 기울기 |
| **단위 불일치** (재무 천원 / 급여만 원) | 1000배 스케일 오차 | 급여는 재무 축 범위 밖으로 분리(단위보정은 ETL 담당) |
| **업종코드 포맷 연도별 상이** (BTP `42500` vs `C29199`) | 그룹핑 키 불일치 | 정규화 그룹은 포맷 일관된 **KODATA `KSIC코드(11차)`** 사용 |
| **결측 다수** | 한 기업 불량값에 파이프라인이 멈추면 안 됨 | 모든 방어 함수 **예외 없이 NaN 반환**(배치 안전) |
| **표본 편향** (샘플 11개 전원 2회+ 반복선정) | 분포가 일반 신청기업과 다를 수 있음 | 절대 임계값 대신 **상대 백분위**로 스코어링(분포 가정 최소화) |

## 3. 공통 방어 모듈 (`finance_utils.py`)

팀원 B도 재사용하므로 먼저 견고하게 완성. 전부 스칼라·Series 대응, 결측·0·음수·inf → NaN.

| 함수 | 역할 | 왜 필요 |
| --- | --- | --- |
| `safe_cagr(start,end,years)` | 연평균성장률 | start/end≤0 방어 → **이익류 CAGR 금지** 구현 |
| `safe_ratio(num,denom)` | 비율 | 분모 0/음수 방어 → 부채비율·이익률·R&D비율 공용, **자본잠식 자동 차단** |
| `winsorize(series)` | 극단값 clip | 비율 이상치가 추세·평균 왜곡하는 것 방지 |
| `slope(values)` | 추세 기울기 | 이익류를 CAGR 대신 방향으로 평가. 결측 위치 유지·유효점<2면 NaN |

## 4. 파생컬럼 24개 — 무엇을 재고, 왜 만들었나

축별 정의는 `features_finance.py` 및 별도 정의서 참고. 여기서는 **설계 인사이트**(왜 이 컬럼이 필요한가)를 정리.

### 축1 성장성 (6개)
매출·자산 각각 **CAGR / 성장안정성 / 성장가속도**. 성장은 "얼마나 빠르게(CAGR)"만이 아니라 **"안정적으로(안정성=YoY 표준편차)"**와 **"지금도 가속 중인가(가속도)"**를 함께 봐야 반짝 성장을 걸러낸다. 자산도 매출과 대칭으로 두어 "외형이 실제로 커졌나"를 교차 확인.

### 축2 수익성 (11개)
- 기본 마진 3종(영업이익률·순이익률·매출총이익률)은 전부 **분모가 매출**.
- **ROA·ROE 추가 이유**: 매출 기준 마진은 "자산·자본을 얼마나 잘 굴려 버는가"를 못 잡는다. ROA(자산 대비)·ROE(자본 대비)로 **자본 효율 관점**을 채움.
- **영업외손익비중(순이익률−영업이익률)**: 우리가 발견한 **"영업흑자인데 최종 적자"(1878)** 함정을 숫자 하나로 정량화. 본업과 최종 실적의 괴리를 자동 노출.
- **흑자지속성**(연수)·**수익성추세/ROA추세/ROE추세**(기울기): 이익류를 CAGR 대신 방향·지속성으로 평가.

### 축3 효율성 (1개) — 신설
**총자산회전율(매출/자산)**. 성장(크는가)·수익(버는가)과 독립된 **"가진 자산을 매출로 뽑는 힘"**. 예: 1878은 마진 최고인데 회전율 최저 → 자산이 놀고 있음(매출 감소의 다른 얼굴).

### 축4 안정성 (6개)
- **부채비율** + **자기자본비율(자본/자산)**: 후자는 부채비율(배수)의 **0~1 직관 버전**. 2080의 과다부채(26.5배)가 자기자본비율 0.036으로 한눈에.
- **자본잠식_플래그 / 자본잠식정도 / 이익잉여금축적**: 원금 훼손을 단계적으로 포착(플래그=완전잠식, 정도<1=진행, 이익잉여금 음수=원금 까먹음).
- **부채비율추세**: 빚을 줄이는 중(디레버리징)인지 늘리는 중인지.

## 5. 스코어링 설계 근거 (`scoring_finance.py`)

### 왜 업종내 백분위 + fallback인가
raw 24개는 단위·스케일이 제각각(부채비율 26.5배 / CAGR 0.2 / 흑자지속성 0~5)이라 그대로 합산 불가. 세 방식 중 선택:

| 방식 | 채택 여부 | 이유 |
| --- | --- | --- |
| **업종내 백분위 + fallback** | ✅ | 등수 기반이라 **극단값에 강건**(부채비율추세 −20도 그냥 꼴찌), **업종 공정**(제조업 vs SW 직접 비교 안 함), **"동종 상위 X%"로 직관적**. CLAUDE.md '업종 평균 대비 백분위' 요구 부합 |
| 전체 백분위만 | ✗ | 업종 특성이 점수에 새어듦(제조업은 원래 자산회전율 낮음) |
| z-score | ✗ | 우리 데이터의 극단값에 표준편차가 부풀어 정상 기업이 뭉개짐, 해석도 비직관 |

- 그룹 = `KSIC코드(11차)` 앞 3자(중분류, 예 `C29`). 그룹 < `MIN_GROUP`(기본 5)이면 **전체 대비로 fallback**.
- 방향 자동 보정: '낮을수록 좋음'(부채비율·성장안정성·판관비율·부채비율추세)은 `100−백분위`로 뒤집어 **항상 높은 점수 = 좋음**.
- ⚠️ 샘플 11개는 업종이 대부분 1곳이라 **전원 fallback(전체)** 경로. 본선 대규모에서 업종내 백분위가 실제 작동.

### 왜 축별 4개, 종합점수 없음
"3축 겹쳐읽기"가 이 도구의 핵심 가치다. 종합점수 하나로 뭉개면 **축 어긋남이 사라져** 도구 의미가 없어진다. 실증: 스코어링 결과 **평균 최하위는 2379가 아니라 616**이었다 — 2379는 수익성·안정성 최악이지만 효율성·성장성이 평균을 끌어올림. 즉 평균은 "만성적자·자본훼손"이라는 진짜 위험을 가린다. → **축별 점수를 나란히** 보여주고 종합은 만들지 않음.

### 왜 특수컬럼은 점수 제외
- **영업외손익비중**: 비단조(음수=손실 나쁨, 큰 양수=일회성 이익도 지속성 낮음) → 방향 하나로 못 정함 → **맥락 컬럼으로 passthrough**.
- **자본잠식_플래그**: 정의상 리스크(백분위 대상 아님) → **대시보드 배지용 passthrough**. 억지로 점수에 섞지 않아 "절대 임계값 금지" 원칙 유지.

## 6. 3축 겹쳐읽기 사례 (발표 하이라이트)

한 축만 보면 오판하는 "축 어긋남" 기업이 심사의 핵심. **전 축 좋음(1049)·전 축 나쁨은 쉬움. 어긋남이 어렵고, 여기서 실수가 난다.**

| 기업 | 한 축만 보면 | 실제(겹쳐보면) |
| --- | --- | --- |
| **695** | 성장성↑ (CAGR 32%, 매출총이익률 60%) | 흑자지속성 1/5, 이익잉여금 −14억 → **고성장이지만 아직 적자·원금 잠식** |
| **1878** | 영업이익률 12.4% (11개 중 1등) | 순이익 적자(영업외손익비중 −0.24) + 효율성 9.1점 → **본업은 버는데 최종 적자·자산 놀림** |
| **2080** | 성장 보통, 매출 105억 | 안정성 12.7점(부채 26.5배) → **성장 숫자로는 안 보이는 재무 폭탄** |

## 7. 엣지케이스 대응 (전수 스윕 + 실증 감사 결과)

파이프라인을 함수별·컬럼별 전수 스윕하고 **합성 엣지케이스 기업 14개로 실제 실행 검증**했다. 크래시가 아니라 **"조용히 틀린 값"**이 진짜 위험이라는 관점에서 하드닝. 검증 코드: `backend/etl/test_edge_cases.py` (28개 assert).

### 조용한 오류 → 수정됨
| 케이스 | 이전 동작(실증) | 현재 동작 |
| --- | --- | --- |
| 영업이익 전결측 | 흑자지속성 **0** — 5년 적자와 구분 불가 | **NaN** + `흑자관측연수` 병기("3년 관측 중 2년 흑자") |
| 본선 컬럼명 변형(`영업이익손실`→`영업이익`) | 무경고 매칭 0개 → 수익성 전멸 + 흑자지속성 전기업 0 | 엄격 매칭 실패 시 **⚠️⚠️ 명시 경고** + 부분일치 fallback |
| 힌트 과매칭 | 가짜 `매출액증가율_2024`가 진짜 `매출액_2024` 매핑을 **덮어씀** | 엄격 매칭(연도 접미사 제거 후 스템=힌트)이 차단 |
| 유효 전이 <3개 | 가속도 0("변화없음" 오독) 또는 창 겹침 희석 | **NaN** (정보부족을 정직하게) |
| `기업일련번호` 중복 | 무경고 통과, 서로를 상대로 백분위 산출 | 경고 + 첫 행만 유지 |
| 판관비 음수(회계 모순) | 조용히 통과 | `데이터모순_판관비음수` 플래그(점수 미반영) |
| 유효값 1~2개 컬럼 | 그 기업이 근거 없이 **백분위 100** | `MIN_VALID`(3) 미만이면 컬럼 백분위 제외 |
| 결측 많은 기업 | 축점수가 올라가기도(실증: CAGR만 NaN → 성장성 52→69) | 유효 컬럼 <절반이면 축점수 **NaN** + `유효컬럼수_*` 출력 |
| KSIC 결측/포맷 혼재(`42500`) | pandas3에서 결측 치환 죽은 코드·그룹 조각화 | isna 명시 처리, 비정상 포맷 `__NA__` 강등 → 무조건 전체 fallback |
| 가장자리 연도 결측 | CAGR 전체 NaN | 기업별 **첫/끝 유효연도**로 계산(span 실제 차이) |
| 연도 컬럼 띄엄띄엄 | slope가 등간격 취급(기울기 2배 과대 실증) | `slope(x=실제연도)` — 간격 반영 |
| 영업이익률 원본 없음 | 수익성추세 NaN | 영업이익/매출×100 대체 계산 fallback |

### 설계상 의도된 동작 (방어 확인됨)
- 자본총계 ≤ 0 → 부채비율 NaN + `자본잠식_플래그`=1 (NaN과 플래그가 짝)
- 자본 음수일 때 자본잠식정도 음수 = "원금 완전 잠식"으로 **의미 있음** (NaN 아님)
- 납입자본금 ≤ 0 → 자본잠식정도 NaN / 매출 시작 0 → CAGR NaN / 이익류 CAGR 금지
- **극단값**(부채비율 수십 배, 극소기저 CAGR 수백%)은 raw에 남지만 **백분위(등수)가 흡수** — 스코어 왜곡 없음. z-score였으면 깨졌을 지점
- `MIN_VALID`·`MIN_AXIS_RATIO`는 절대 임계값이 아니라 **등수 산출의 최소 표본 조건**(통계 신뢰 가드) — "임계값 하드코딩 금지" 원칙과 구분

## 8. 한계 & 다음 단계

- **표본 한계**: 샘플 11개는 전원 반복선정 큐레이션 → 분포 편향. 업종 백분위는 본선 데이터에서 의미(샘플은 fallback).
- **범위 밖(다음 단계)**: 축 가중치 조정, 대시보드 시각화, 자본잠식 플래그의 대시보드 강조, 타 축(기술력·고용·정합성)과의 통합 스코어카드.
- **본선 당일**: `--source db`로 팀원 C의 Postgres에 연결(테이블명 config 상수만 맞추면 됨). 지금은 parquet로 로직 검증 완료.
