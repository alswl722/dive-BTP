# 축8 Claude API 비용 시뮬레이션 (결제 승인 근거자료)

> 담당: 팀원 D (형우, 기술리드) · 관련: `docs/축8_LLM_인터페이스.md` (설계), `docs/축8_설계노트.md` (전체 축8)
> 근거 단가: Anthropic 공식(2026-04 캐시 기준, claude-api 스킬)

---

## 1. 목적

축8 정합성 판정 LLM 호출에 필요한 Claude API 사용료를 본선 데이터 규모별로 추정 → 팀 결제 승인 요청 근거.

**결론 미리**: 최악의 시나리오(5000 기업, 판단유보 40%, Opus 4.7)에서도 예상 비용 **약 $50 이내**. 데모·본선 완주에 결제 부담 없음.

## 2. 최신 Claude 단가 (2026-04 기준)

| 모델 | 입력 $/1M | 출력 $/1M | Cache Read $/1M | Cache Write (5m) $/1M |
| --- | ---: | ---: | ---: | ---: |
| Claude Opus 4.7 (default) | 5.00 | 25.00 | 0.50 | 6.25 |
| Claude Sonnet 4.6 | 3.00 | 15.00 | 0.30 | 3.75 |
| Claude Haiku 4.5 | 1.00 | 5.00 | 0.10 | 1.25 |

- Cache Read = base input × 0.1
- Cache Write (5min TTL) = base input × 1.25
- 축8은 batch 판정이라 5분 TTL이 적절 (1시간 TTL은 write 2배)

## 4. 판정 파이프라인 가정

**Phase 2 실측** (샘플 데이터 92건):
- Whitelist 통과: 91.3%
- **판단유보 → LLM 호출**: 8.7%

**본선 데이터 시나리오**:

| 시나리오 | 판단유보율 | 근거 |
| --- | ---: | --- |
| **낙관** (샘플과 동일) | 8.7% | 본선 조합이 샘플에서 대부분 관측됨 가정 |
| **중간** (권장 가정) | 20% | KSIC 대분류 다양성 증가(현재 3종 → 본선 5종+) 반영 |
| **보수** (안전 여유) | 40% | 신규 조합 대량 출현 최악 시나리오 |

**앱 레벨 dedup 캐시 히트율**: **40%** (같은 (company, business_type) 조합 반복 활용)
→ 실제 API 호출 = 판단유보 건수 × 0.6

**Anthropic prompt cache 히트율** (fresh 대비 read 비율):
- System prompt: 첫 호출만 write, 이후 100% read
- 사업목적: 기업당 첫 판정만 write, 이후 read

## 6. 모델 선택 권고

### 6.1 default: **Opus 4.7**
- claude-api 스킬 원칙 준수 ("사용자가 명시적으로 다른 모델 지정 안 하면 Opus 4.7")
- 축8은 시맨틱 정합성 판단 — 어휘 겹침 없는 케이스 정확 처리가 핵심. Opus 4.7의 지시 따름 정확도가 gold label 튜닝 부담 감소
- 본선 최악 시나리오 $48.80로도 팀 예산 부담 없음

### 6.2 비용 민감 옵션: **Sonnet 4.6**
- 판정 재현성·품질 손실 미미 예상 (structured output 단순 판정 태스크)
- 비용 40% 절감
- 결제 승인 지연 시 fallback 후보

### 6.3 극한 비용 옵션: **Haiku 4.5**
- 시맨틱 뉘앙스 판정 품질 저하 가능성 (특히 간접관련 경계)
- Gold label 튜닝 노력 증가 예상
- 극단적 예산 제약 시만 검토

**결정 사항**: Phase 3 스텁의 `DEFAULT_MODEL = "claude-opus-4-7"`. 팀 협의로 변경 가능하도록 config 파라미터화 예정 (Phase 5).

## 7. 리스크·불확실성

| 항목 | 방향 | 대응 |
| --- | --- | --- |
| **판단유보율 실측 미확인** | 위험 ↑ | 보수(40%) 시나리오도 $50 이내 → 예산 여유 |
| **본선 데이터 기업 수 불명** | 양방향 | 브리핑상 "1,200 기업 지원" → 5,000까지 여유 확보 |
| **사업목적 텍스트 길이 편차** | 위험 ↑ | ~200 tokens는 평균 가정, 실제 10개 항목 채우면 400~500 tokens 가능 → 20% 상향 여유 |
| **Anthropic 단가 변경** | 미상 | 시뮬은 2026-04 캐시 기준. Model API의 라이브 lookup으로 재확인 가능 |
| **캐시 히트율 미달** | 비용 ↑ | 40% dedup 가정. 실측 후 재산정 — Phase 5 통합 후 첫 batch에서 히트율 로깅 |
