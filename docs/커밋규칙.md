# 커밋 & 브랜치 규칙 (FoeDev)

> 팀원 4명이 서로의 작업을 커밋 로그만 보고도 이해할 수 있게 하는 최소 약속.
> 이미 쓰고 있는 방식(`feat(etl): …`)을 문서로 고정한 것 — 새로 배울 건 없다.

---

## 1. 커밋 메시지 형식

```
<type>(<scope>): <요약>

<본문 — 필요할 때만>
```

**요약 줄 (필수)**
- 한글로, **무엇을 했는지** 한눈에. 50자 내외.
- 끝에 마침표 안 붙임.
- "~함/~추가/~수정"처럼 **한 일**을 적는다. ("~하기", "~할 예정" 금지)

**본문 (선택 — 요약만으로 부족할 때)**
- 요약 줄과 **빈 줄 하나** 띄우고 작성.
- **무엇을** 바꿨는지보다 **왜** 그렇게 했는지를 남긴다 (코드는 what을 이미 말해줌).
- 팀원이 이 커밋을 나중에 볼 때 궁금할 결정·트레이드오프·주의사항을 적는다.

---

## 2. type (무엇을 하는 커밋인가)

| type | 쓸 때 |
|---|---|
| `feat` | 새 기능·새 파생컬럼·새 엔드포인트 등 **기능 추가** |
| `fix` | 버그·오작동·잘못된 계산 **수정** |
| `refactor` | 동작 그대로 **구조만 개선** (결과값 안 바뀜) |
| `chore` | 빌드·설정·`.gitignore`·의존성 등 **잡일** |
| `docs` | 문서만 변경 (설계노트·README·이 문서 등) |
| `test` | 테스트 추가·수정 |
| `style` | 포맷·공백·주석 등 **로직 무관** 변경 |

---

## 3. scope (어느 영역인가) — 폴더 기준

| scope | 영역 |
|---|---|
| `etl` | `backend/etl/` — 적재·파생컬럼·스코어링 |
| `api` | `backend/app/` — FastAPI 라우터·스키마·서비스 |
| `db` | `db/` — 마이그레이션·스키마 SQL |
| `frontend` | `frontend/` — Next.js 화면·컴포넌트 |
| `infra` | docker·compose·배포·환경 |
| `docs` | `docs/` 문서 |

- 여러 영역이면 대표 하나만. 애매하면 `scope` 생략 가능 (`feat: …`).
- 축 작업은 scope=`etl`에 요약으로 축을 명시. 예: `feat(etl): 기술력 3축 파생컬럼 추가`

---

## 4. 브랜치 규칙

- `dev`에 **직접 커밋하지 않는다.** 항상 브랜치를 파고 PR로 병합.
- 브랜치명: `feature/<주제>` (예: `feature/tech-axis`, `feature/frontend-skeleton`)
  - 버그픽스 성격이면 `fix/<주제>`도 가능.
- 한 브랜치 = 한 주제. PR 제목도 커밋 요약과 같은 형식으로.
- 병합 대상은 `dev`. `main`은 안정판.

---

## 5. ⚠️ 금지 (반드시)

git에 올라가는 어떤 곳에도 **AI/도구 기여 표기를 넣지 않는다.**
(CLAUDE.md 개발원칙 6)

- ❌ `Co-Authored-By: Claude …`
- ❌ `🤖 Generated with …`, `made by …`
- ❌ 커밋·PR 본문·코드 주석 어디에도

커밋은 **작업한 팀원 본인 이름**으로만 남는다.

---

## 6. 예시

**좋은 예** (실제 히스토리 스타일)
```
feat(etl): 재무 3축 파생컬럼 + 공통 방어 모듈
feat(api): FastAPI 라우터 구현 (companies/rankings/dashboard)
fix(frontend): 지원이력 목업을 실제 support_records 데이터로 교체
fix(infra): docker compose 전체 스택 부팅 실패 수정
```

**본문까지 쓰는 예** (왜를 남김)
```
fix(etl): NTIS 주관 과제수 중복 집계 수정

기준일자 스냅샷 구조라 한 과제가 여러 행으로 들어옴(172행→61과제).
(company_id, 총연구기간, 사업명)으로 dedup. 안 하면 수주건수가 2.8배 부풀려짐.
```

**나쁜 예**
```
update              → 무엇을 했는지 모름
수정함               → type·scope 없음, 뭘 고쳤는지 모름
feat: 작업중          → 미완성/진행형 금지
fix(etl): 버그수정 🤖  → AI 표기 금지, "버그수정"은 무슨 버그인지 불명
```
